# env-to-ini

Convert dotenv (`.env`) files to INI configuration format with prefix-based
section mapping. Zero dependency, pure Python 3.9+ standard library.

## Features

- Reads dotenv files from a path or stdin (`-`)
- Three section mapping strategies:
  - flat: everything under `--section NAME` (default)
  - prefix: `--prefix-keys` maps `DB_HOST` to `[db] HOST` (`--keep` keeps the full key)
  - explicit: `--map FILE` with `KEY=section` overrides (highest precedence)
- Preserves `# comments` as INI `;` comments (`--comments`)
- Quoting rules: unsafe values (#, ;, escapes, padding) are re-quoted, safe
  values pass through bare
- `export` prefixes, single/double quotes, escapes and inline `#` comments
  follow python-dotenv semantics
- CI gates: `--check`, `--max-warnings N`, `--require-sections`,
  `--forbid-section` (all exit 2 on failure)
- `--json` writes a machine report on stderr **without ever printing values**
- `--sort`, `--output FILE`, `--in-place`, `-q/--quiet`

## Usage

```bash
# flat conversion from stdin
printf 'A=1\nB=2\n' | env-to-ini -

# prefix-based sections: DB_HOST -> [db] HOST
env-to-ini --prefix-keys .env

# keep full key names under prefix sections
env-to-ini -k --keep .env -o config.ini

# explicit overrides via a mapping file
printf 'DB_HOST=infra\nDB_PORT=infra\n' > sections.map
env-to-ini --prefix-keys --map sections.map .env

# lint in CI: fail if any key can't be prefixed, require sections
env-to-ini --prefix-keys --check --require-sections db,app .env || echo FAILED

# JSON report on stderr (values are never included)
env-to-ini --json .env 2> report.json

# rewrite the file in place
env-to-ini --sort --comments --in-place .env
```

## Example

```
$ cat .env
# application
APP_NAME=demo
DB_HOST=localhost
DB_PORT=5432
SECRET="token #v2"

$ env-to-ini --prefix-keys --comments .env
; generated by env-to-ini

; application
[app]
NAME = demo

[db]
HOST = localhost
PORT = 5432

[default]
SECRET = "token #v2"
```

## Mapping file format

One `KEY=section` (or `KEY: section`) per line, `#` comments allowed:

```
BARE_KEY=core
DB_HOST=infra
# everything else falls back to --prefix-keys / --section
```

Precedence: `--map` > `--prefix-keys` > `--section` default.

## Exit codes

| Code | Meaning                                               |
|------|-------------------------------------------------------|
| 0    | success                                               |
| 1    | CLI or I/O error (unreadable file, bad usage)         |
| 2    | lint gate failed (--check, --max-warnings, sections)  |

## Notes

- Keys without an underscore under `--prefix-keys` warn and fall back to the
  default section (use `--check` to fail in CI).
- Invalid lines are skipped with a warning, never guessed.
- Blank dotenv entries (`FLAG` without `=`) are emitted as empty values.
